# 使用说明

双击 `CodexQuotaMonitor.exe`。需要已登录的 Codex 桌面客户端和 PowerShell 7，程序优先使用 Codex 自带的运行环境，不打开终端。

## 查询和暂停

- 常规间隔：1–3600 秒。
- 低额度触发：五小时剩余 ≤设定值时，改为低额度间隔；实际取常规和低额度间隔中更短的一个。
- 默认常规 30 秒，剩余 ≤10% 时 10 秒；等待暂停或继续结果确认期间也使用较短间隔。没有实际执行中项目或活跃目标时恢复常规间隔，即使额度仍低也不加速。已空闲的监控记录不会使查询保持加速。
- 默认五小时剩余 ≤5% 暂停。账号不允许使用或周额度耗尽时也暂停。
- 修改数字后点“保存并应用”；开关和聊天勾选自动保存。
- 每轮查询会重新创建独立 app-server 读取进程，防止长时间复用返回旧缓存。查询结束后开始计算等待时间，查询本身还需客户端响应；额度卡片按真实查询更新，倒计时每秒刷新。

“五小时额度耗尽”“周额度耗尽”“账号消费上限已触发”和服务暂不允许使用分开显示。额度为 0% 不再写成“账号不可用”。未知的额度字段显示“未提供”，不当作 0%。

## 连续失败处理

默认不勾选“连续失败后自动停止监控”，普通连接或读取失败会持续重试，不再固定五次就停止；升级旧设置也采用这个默认值。失败后按常规查询间隔重试，日志和窗口显示当前连续失败次数，成功查询后计数归零。

需要自动停止时，勾选该项，填写 1–9999 次，再点“保存并应用”。达到次数后停止监控，可排查后点“启动监控”；不停止聊天、不清除已暂停记录。单个聊天连续操作失败使用同一上限，只停止该聊天的自动处理。取消勾选立即保存为持续重试。

持续重试针对暂时的连接/读取错误；原任务身份校验、未知通信协议、暂停/继续结果未确认等保护仍有效，不重复提交结果未知的继续请求。

## 聊天列表与自动继续

默认仅显示正在执行、等待输入、目标待续、正常监控、已登记待续、手动保持暂停和需要排查的相关项目。勾选“显示所有项目”后，包括本机未归档的空闲、已结束、未加载桌面项目。该开关会保存；标题过长时将鼠标停在标题上查看完整内容。

“执行中 2（普通 1，目标 1）”表示共两个执行中的聊天，括号是分类，不是另加两个。活跃目标在轮次之间空闲时，另显示“目标待续”。

每行的“自动继续”可以直接取消或开启，刷新和重开后保留选择。“新聊天默认允许继续”只影响尚未选过的新聊天，已有选择保留。“全选列表”“清空列表”只修改当前可见列表，不覆盖隐藏聊天的历史选择。

自动恢复要求：原任务仍符合资格，五小时额度超过暂停值，周额度可用，服务允许使用，聊天空闲，无待处理审批或输入，再两次检查（至少相隔 5 秒）。提前补充额度后也可以恢复，无需等旧重置时间。取消恢复勾选不影响低额度暂停规则。

“已暂停 N”表示已确认暂停的数量。“恢复后待续 M”表示已登记且获准继续的数量：包括勾选恢复的暂停项目、右键主动登记的项目及等待加载的开始请求。手动保持暂停、取消勾选或未登记的历史项目不计入；只读观察不会继续，待续数显示 0。仍有输入、审批或加载等待时，具体原因显示在每一行。

## 项目右键菜单

- **手动暂停（保持暂停）**：正在执行的项目请求中断并核实结果；空闲项目保持手动暂停。额度恢复后仍不自动开始，直到你主动开始或登记自动继续。
- **手动开始 / 继续**：在额度可用、没有输入/审批待处理时开始一次。额度不足时保存请求，等待可用后执行；已在执行则不重复提交。
- **登记自动继续（空闲 / 已结束也可）**：同时开启该项目的恢复许可，并登记一次继续请求。项目可处于空闲、已结束、额度中断或暂停状态；通过检查后执行一次，不形成无限重启循环。已执行中的项目保持监控。
- **取消自动继续**：取消勾选及已登记的待续请求；不会停止正在执行的项目。

未加载项目的开始/自动继续操作会尝试通过 Codex 链接打开原项目，后台等待客户端加载后核实并执行；自动打开失败时日志提示手动在客户端打开。不会仅凭历史目录推断当前任务状态。已归档或删除的项目不执行。

只读观察时右键操作不可用；暂停/继续结果正在确认时，新的控制请求会提示等待，避免重复提交。项目请求会持久保存，日志记录登记时间、项目标题、操作和实际确认结果。新图标已内嵌 EXE，并用于窗口及托盘。

## 额度中断

遇到 `usageLimitExceeded` 错误或目标 `usageLimited`，程序登记为额度中断等待恢复。包括最新一轮仍明确报告额度中断、但被旧版误标为结束的记录。额度恢复且勾选允许后，继续原任务并要求检查已有进度。

普通 `completed` 是本轮执行结束，不代表整个项目完成；不会无条件重启已结束聊天。其他错误记录为失败，用户修改目标、开始新任务或手动接管时取消旧恢复资格。已归档或删除的聊天不恢复；目标预算限制不自动解除。

## 自动重置卡

默认关闭。勾选后按“周剩余 ≤X%”触发，默认 X=1。卡数未知、没有符合条件的卡、只读观察或测试模式时不消耗卡。服务器决定重置资格，不能保证任意阈值都能成功。

每次只请求一张，优先最早到期的可用 Codex 卡。请求编号在发送前持久化，超时和重启后沿用同一编号；未确认请求至少相隔 30 秒核实。成功后重新读取两项额度和卡数，若额度还未回升，不连续消耗其他卡。

服务器“没有可重置窗口”时等待耗尽、窗口或卡数变化；“没有可用卡”显示该结果。“设置已保存”和“服务器确认使用”是不同事件，设置开关不代表已经使用卡。

## 日志、托盘和退出

“查看日志”打开完整历史。支持日期、聊天或内容、暂停/继续/额度/重置卡/错误/启停/设置等筛选；CSV 导出使用 UTF-8 BOM，适合 Excel。列表显示最近 2000 条，导出全部匹配结果。暂停和继续以确认事件为准，未知历史字段显示“未记录”。

最小化或点右上角关闭会驻留托盘。双击托盘图标恢复窗口。“停止监控”停止查询与自动控制，不停止当前聊天；“退出程序”等待后台结束后退出。普通运行有实例互斥；独立只读验证不会控制实际聊天。

## 升级与状态迁移

先在旧窗口点“退出程序”，再启动新版。不要同时运行两个自动监控器。

已有项目目录的旧用户：把新版 EXE 放在原交付目录，即包含原 EXE 和 `src` 的目录。新版会寻找两级上方的 `work/quota-monitor-v1/all-Auto`，沿用暂停记录和日志，并把状态目录保存到设置。以后移动 EXE 仍能沿用已保存路径。

单独使用发布文件的新用户：默认数据位于 `%LOCALAPPDATA%\CodexQuotaMonitor\state`。设置位于同一父目录的 `settings.json`；程序没有开机自启或系统服务。

若旧数据在其他位置，退出所有监控后，备份 `settings.json`，将其中的 `stateDirectory` 设为旧总状态目录的绝对路径（JSON 中反斜杠需写成 `\\`），或者把旧状态目录完整复制到默认 `state`。保留 `state.json`、总日志和 `threads` 子目录，不单独删除暂停登记。

公开仓库仅包含源码、测试和演示截图；账号凭据、实际聊天、设置、运行日志及个人工作目录不随源码发布。
